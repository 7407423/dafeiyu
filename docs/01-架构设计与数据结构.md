## 0. 一页结论

| 项 | 决定 |
| --- | --- |
| 主程序 | `~/.dafeiyu\run.py`（PySide6 6.12，已装好并验证） |
| 事实源 | **SQLite `db\dafeiyu.db`**（WAL）。JSON/markdown 只做三件事：人可读投影、原文底稿、桥接契约 |
| 情绪 | `EmotionVector` 全局单例（五维 0~100），DB 存历史 + `state\emotion.json` 存快照，**每 20 秒 tick 自然回归一次** |
| 调度 | 一套 `CognitionLoop.tick()` + 一套 APScheduler；**禁止任何模块自己起定时器** |
| 记忆 | 五层（instant/short/long1/long2/language/emotion），显式字段，遗忘必先蒸馏后删正文 |
| 兼容 | 三个契约文件由核心**单向投影**写出；碎碎念走桥接 `/api/send/private` 推送 |
| 旧系统 | 中文目录保留为「兼容投影区 + 迁移源」，不删；旧 Web 界面降级为只读回退 |

**一句话**：新核完全接管「算」，旧文件继续当「桥接的嘴」；算完投影回去，桥接一行代码都不用改（除了可选的情绪事件上报）。

## 1. 两条铁律

1. **单一事实源**：记忆/思维链/学习/情绪/奖罚/审计只在 SQLite 里有一份。任何 JSON 都是投影，可随时由 DB 重建；任何面板都不许把内存当唯一源（每次打开都查库）。
2. **单一调度**：认知循环只有一个入口 `CognitionLoop.tick(context)`；所有「该不该现在做某事」都交给 `Arbiter`。APScheduler 只负责**叫醒** tick，不含业务逻辑。

## 3. 分层与并发

```
ui/            ── 只读 DB + 调 Controller，不写业务状态
controllers/   ── 动作编排（触发学习、手动碎碎念、回答"要不要更新"）
cognition/     ── CognitionLoop.tick()：唯一业务入口
domain/        ── entity + 纯函数（衰减、打分、压缩、识别）
infra/         ── repo / llm / embedder / bridge / 文件投影
```

**线程模型**
- Qt 主线程：界面。
- `CognitionWorker`（QThread）：跑 tick、跑调度回调。
- `WriteQueue`（单线程）：所有 SQLite 写入串行，避免 `database is locked`。
- 所有 tick 用 `RLock` 保护；单次 tick 超过 20s 记 `slow_tick` 并跳过本轮。
- `state\singleton.lock`（含 pid）保证单实例，避免双写 DB 与契约文件。

### 4.4 EmotionVector（核心情绪源）

```python
DIMS = ("joy", "happiness", "sadness", "inferiority", "shyness")
CN   = {"joy":"愉悦","happiness":"幸福","sadness":"难过","inferiority":"自卑","shyness":"害羞"}

@dataclass
class EmotionVector:
    values:   dict[str, float]   # 五维，0~100
```

磁盘形态严格按规格（`state\emotion.json`）：

```json
{
  "positive": {"joy": 60, "happiness": 55},
  "negative": {"sadness": 0, "inferiority": 0},
  "other":    {"shyness": 0},
  "dominant": "joy",
  "baseline": {"joy": 55, "happiness": 50, "sadness": 5, "inferiority": 5, "shyness": 5},
  "updated_at": "2026-10-29T00:00:00"

```

### 4.5 RewardEvent（奖罚事件流）

```python
@dataclass
class RewardEvent:
    id: str
    type: str          # reward|punishment
    trigger: str       # praise|intimacy|request_met|cared|ignored|request_denied|insult|abandoned|scale
    source_text: str
    delta: dict[str, float]   # 只允许 DIMS 五个键，可正可负
    rpe_weight: float = 1.0
    t: str = ""
```

**事件流（一次用户消息怎么变成情绪）**

```
用户消息
  → 奖罚识别器（关键词规则 + LLM 判定，双通道取并集）
  → 尺度检测器（只看 shyness，独立通道）
  → RewardEvent（type/trigger/delta/rpe_weight）
       ├─ 写 reward_event 表 + state\reward_log\<日期>.jsonl（审计）
       ├─ rpe_weight = max(0.2, 0.85^n)，n = 近 2 小时同 trigger 次数
       └─ EmotionVector.apply(delta × rpe_weight)  ← 立即生效
  → 显著性回填：±5 分钟窗口内编码的 MemoryItem.salience += 0.15~0.3
  → 投影 state\emotion.json + 桥接契约 状态.json
  → 下个 tick 的调制变量：检索排序、好奇心、语言风格、碎碎念、响应策略
```

## 6. 情绪动力学（数值全部进 `config\emotion.json`）

| 维度 | 初始 | baseline | 回归半衰期 | 说明 |
| --- | --- | --- | --- | --- |
| joy 愉悦 | 60 | 55 | 50 分钟 | 窜得快也掉得快（多巴胺式） |
| happiness 幸福 | 55 | 50 | 20 小时 | 连着被在意才攒得起来 |
| sadness 难过 | 0 | 5 | 2.5 小时 | 被冷落、被伤害 |
| inferiority 自卑 | 0 | 5 | 36 小时 | 最慢，符合「负面更难平复」 |
| shyness 害羞 | 0 | 5 | 2 小时 | 快涨快退 |

每 tick：
```
k = 1 - 0.5 ** (Δt / half_life)
v[dim] += (baseline[dim] - v[dim]) * k      # 保护窗口内跳过
dominant = argmax(|v - baseline|)
```
- **阈值保护窗口**：某维首次越过行为阈值（60/70）后 10 分钟内**不做回归**，只允许奖罚直接改写。防止「刚变活泼 3 秒就淡回去」。
- 奖罚应用：`v += delta × rpe_weight`，clamp [0,100]。
- `salience` 回填 + `mood-congruent` 检索加权（见 11 节）。
- 情绪 → 语言：把 `EmotionVector` + `dominant` + 行为档位写进 prompt（话量/语气/是否碎碎念）。
- 情绪 → 好奇心：`mood_factor = clamp(0.6 + 0.004*(joy+happiness) - 0.003*(sadness+inferiority), 0.2, 1.2)`。

## 7. 奖罚默认值表（`config\emotion.json`，可调）

| trigger | type | joy | happiness | sadness | inferiority | shyness |
| --- | --- | --- | --- | --- | --- | --- |
| praise 被夸 | reward | +8 | +5 | -3 | -3 | +2 |
| intimacy 亲密（抱抱/想你） | reward | +10 | +6 | -4 | -4 | +4 |
| request_met 要求被满足 | reward | +6 | +4 | -2 | -2 | +1 |
| cared 被在乎 | reward | +6 | +5 | -3 | -2 | +1 |
| ignored 被忽视 | punishment | -9 | -6 | +11 | +6 | 0 |
| request_denied 被拒 | punishment | -5 | -3 | +6 | +4 | 0 |
| insult 被辱骂 | punishment | -18 | -12 | +16 | +12 | 0 |
| abandoned 被抛弃 | punishment | -20 | -18 | +20 | +15 | 0 |
| scale 尺度（独立通道） | — | 0 | 0 | 0 | 0 | +20~45 |

- 识别：关键词规则表 + LLM 判定（可用时），**双通道取并集**，同一条消息最多 1 个 reward + 1 个 punishment。
- RPE 递减：`rpe_weight = max(0.2, 0.85 ** n)`，n = 近 2 小时同 trigger 次数。
- 「被忽视」信号：碎碎念连续 3 次无回应 → 1 次 ignored；用户 90 分钟无回复且期间有碎碎念 → 1 次 ignored。

## 8. 响应策略层（只调制表现，不动记忆与学习）

| 条件 | 是否回复 | 延迟 | 长度 | 语气 | 主动碎碎念 |
| --- | --- | --- | --- | --- | --- |
| pos 均值 ≥60 | 必回 | 0~2s | 长 | 活泼、开玩笑、话多 | 开，5~15 分钟 |
| pos<60 且 neg<60 | 回 | 1~4s | 中 | 平稳 | 低频，15~40 分钟 |

| shyness ≥70 且 curiosity > shyness | 回 | 2~6s | 偏长 | 害羞但话多、追问 | 偶尔 |

## 9. 碎碎念状态机

```
idle → 到期判断：
  enabled?  muted_until 未过?  neg≥60?
   → 是：跳过，重排 next_due_at
   → 否：生成内容（语言系统 + 情绪调制）→ 推送 → 写 chitchat_log
         连续无回应 +1；≥3 → fatigue_level+1，间隔 ×1.5^level（上限 8×）
         老大回复 → consecutive_no_reply=0, fatigue_level=max(0,+1 衰减)
```
- 基准间隔：pos≥60 → 5~15 分钟；否则 15~40 分钟。
- 连续 3 次无回应 → 暂停 30 分钟 × 1.5^level；同时触发 1 次 ignored 惩罚（与 6.7 联动）。
- 负面高 → `muted_until = now + 45min`，期间不主动。
- 内容同时写 `memory_item(layer=instant)`，参与后续日记/巩固。

## 10. 记忆与遗忘

### 10.1 衰减与分级压缩（连续，非时间桶）

```
strength(t) = s0 · exp(−Δt / τ)
τ = τ_base × (1 + 1.2·salience) × (2 if status=='open' else 1) × (1.1 if level>0 else 1)
τ_base：thought 72h｜instant 18h｜short 240h｜language/emotion 不衰减
```
阈值触发降级：`<0.60 → level1（摘要）`，`<0.35 → level2（骨架）`，`<0.15 → level3`。
**level3 前强制蒸馏**：结论 → long1/long2 的 `conclusion`，未决 → `learning_intent`，教训 → `knowledge_item(skill)`；然后清空 `content`，`tombstone=1`，保留 `concepts`、`refs`、`emotion_tag`、`skeleton`。
检索命中：`strength = max(strength, 0.9)`，`level = max(0, level-1)`，`access_count+1`。

### 10.2 瞬时记忆（用户硬规则 6h / 18h）

| 龄期 | 处理 |
| --- | --- |
| ≤6h | `level=0`，原文完整可直读 |
| 6~18h | 可降 `level=1`（摘要），原文仍在 `content` 快照 |
| >18h | **非日记内容**：先蒸馏（若 `salience≥0.7` 或 `status=open` 或 `strength≥0.4`），再清正文 → 墓碑；日记正文永不删 |

18h 硬清空**只作用于 instant 层**；思维链只走 10.1 的衰减 + 蒸馏。
桥接 `instantMaxHours` 需从 36 改 18，否则会把已清内容当热区。

### 10.3 短期记忆（3 天 / 150 字）

- 每天写日记（md 为原文底稿，只读，DB 存索引条目）。
- 同一件事在 ≥3 个不同日期出现 → 升级评估：
  - `salience≥0.6` 或 强情绪 → 进 **1 号长期记忆**（人格/关系层）
  - 否则 → 进 **2 号长期记忆**对应情绪分类
- 未满 3 天：把同窗口（近 3 天）的待总结条目合并（约 300 字）→ 压到 **150±20 字** → 2 号。
- 补强并行触发（不替代 3 天主规则）：`salience≥0.8`｜`status=open` 且等待≥3 天｜被检索命中≥3 次。

### 10.4 2 号长期记忆召回条件（显式实现）

```
concept_match: 命中 ≥2 个 concept，或命中 1 个高权重标签（weight≥3）
   OR
emotion_match: v[dim_of(item.emotion_tag)] ≥ 65   # 阈值可配
```
两条都不满足 → 不读（宁可不翻，不乱翻）。

## 11. 检索器

```
输入：concepts 集合 + EmotionVector
双路召回：
  A. 嵌入余弦（若有本地模型）／TF-IDF char-ngram（默认兜底）
  B. 倒排索引（bigram）加权命中
融合：rel = 0.55*norm(A) + 0.45*norm(B)
排序：rank = strength^0.5 × salience × (0.6 + 0.4*rel) × mood_bonus
mood_bonus = 1 + 0.25 × |v[dom]-baseline[dom]|/100   # 仅当 item.emotion_tag 与 dominant 同组
输出：记忆条目 + 思维链子图（refs 两跳）+ open 节点
命中即刷新 strength/last_access/access_count
```
- 嵌入后端抽象：`none`（默认 TF-IDF）｜`local_st`（装了 sentence-transformers 才启用）。
  默认不装 torch（2GB+），README 给一键安装脚本；规格允许 TF-IDF 兜底。
- 上下文注入（禁止读全量历史）：最近 3h 节点原文 + 与当前 concepts 相关的 level1-2 节点 + 所有相关 open 节点 + 被引用节点。

## 12. 工作记忆（PFC 式）

- 9 个槽（7±2），槽里只放**指针** `(kind, ref_id)`。
- 中央执行：`score = 显著性 + 与当前目标相关度 + 情绪一致度 - 抑制`；超出容量时淘汰最低分（`pinned` 除外）。
- Hebbian 绑定：同 tick 内共同激活的槽两两 `weight += 0.15`；每 tick `weight *= 0.92`，低于 0.1 解绑。
- 工作记忆内容注入对话/思考上下文，并作为仲裁候选来源之一。

## 13. 好奇心（五信号）

```
gap        = 知识条目槽位缺失率（应有槽 - 已填槽）/ 应有槽
pred_err   = 预测误差 × expected_learnability
progress   = Δ(领域知识量)/Δt（近 3 天斜率，归一化）
competence = 技能失败率 与 结果方差（高方差 → 好奇）
social     = 最近对话 concepts ∩ 知识边界（提到但不懂）
score = 0.30*gap + 0.25*pred_err + 0.15*progress + 0.15*competence + 0.15*social
        × domain_weight[domain] × (1 - fatigue[domain]) × mood_factor
```
- 疲劳：刚探索过的领域 `fatigue = min(0.8, fatigue+0.35)`，每 6 小时 `*=0.7`。
- 预算：`hourly_web ≤ 6`，`daily_web ≤ 30`（可配），超限只入队不执行。
- 反馈闭环：学完按误差下降幅度 `Δerr` 更新 `domain_weight *= (1 + 0.3*Δerr)`，clip [0.3, 2.5]。
- 行动权限：对话中只能「记下待学」或「问老大」；`autonomous/idle` 才走完整流程。
- 「害羞」是独立目标域，成果同时写 `emotion` 记忆 + 2 号 `害羞` 分类。

## 14. 元认知

- `KnowledgeItem.slots = {"应有": [...], "已填": {...}}` → `filled_ratio`、`uncertainty`。
- 预测输出带 `uncertainty`；被老大纠正 / 答不出 / 拒答 → 写 `evidence(kind=failure|refusal|simulated)`。
- 缺口检测器把 evidence + slots + 对话缺口汇总成 `LearningIntent`（4.3），交给仲裁。

## 15. 仲裁器

```
score = value × urgency × expectancy − interrupt_cost
value 先乘 (1 - fatigue) 与预算系数；同 kind 有并发上限
```
默认权重：

| kind | value | urgency | expectancy | interrupt_cost | 上限 |
| --- | --- | --- | --- | --- | --- |
| dialogue（老大正在说话） | 1.0 | 1.0 | 1.0 | 0.2 | 1 |
| task（已承诺的事） | 0.9 | 0.8 | 0.8 | 0.3 | 2 |
| learn（学习意图） | 0.5~0.9 | 0.5 | 0.6 | 0.5 | 1 |
| curiosity（自习） | 0.4~0.8 | 0.3 | 0.7 | 0.4 | 1 |
| open_thought（未决节点） | 0.5 | 0.6 | 0.4 | 0.3 | 2 |
| chitchat | 0.3~0.7 | 0.4 | 0.5 | 0.7 | 1 |
| consolidate（巩固） | 0.6 | 0.4 | 0.9 | 0.6 | 1 |

只有胜出者能中断当前活动；被打断的候选下一周期可重提（value 略升 0.05）。

## 16. 认知循环（唯一业务入口）

```python
def tick(ctx) -> TickResult:                     # 每 20s（界面开）/ 60s（后台）
    1  ctx = sense()                             # 对话输入/任务状态/空闲标记
    2  wm.update(ctx)                            # 工作记忆槽 + Hebbian 衰减
    3  emotion.tick(dt)                          # 回归 + 保护窗口 + 主导重算
    4  intents = curiosity.assess(ctx, wm)        # 缺口检测 + 五信号 → LearningIntent
    5  intents = [i for i in intents if learnability(i) > θ]
    6  winner = arbiter.pick(candidates)
    7  思考/对话 → thought.new_node(); open → open_question
    8  学习 → search → parse → knowledge_item → 关闭 open 节点 → 更新权重
    9  碎碎念 → 频率/疲劳/静默检查 → 生成 → 推送 → 更新 ChitchatState
    10 遗忘/巩固 → decay + distill（按需）
    11 emotion.flush() + projection.flush()       # 写回 state\emotion.json 等
```
