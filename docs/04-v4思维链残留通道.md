## 一、现有 ThoughtNode 结构与链/会话标识方式（扫描结果）

### 1.1 列（18 个，全部 NOT NULL 或默认值）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id / chain_id | TEXT | 节点与链 |
| type | TEXT | start/step/branch/decision/conclusion/open_question/reflection |
| content / summary / skeleton | TEXT | 三级压缩载体 |
| concepts / refs | TEXT(JSON) | 概念与引用边 |
| task_ref | TEXT | 任务/会话标记 |
| salience / confidence | REAL | 显著性、置信度 |
| status | TEXT | open/resolved/abandoned |
| strength / level / tombstone | REAL/INT/INT | 原遗忘曲线 |
| t_created / last_access / access_count | TEXT/TEXT/INT | 时间与访问 |

**没有** `last_active_at`、`in_residual`、`session_tag` —— v4 要加的三列都不存在。

### 1.2 数据现状（关键发现）

```
thought_node       13 行
graph_edge          0 行          ← 引用边一条都没有
dialogue_message    0 行          ← 核心没有存过任何对话
按 type/status      decision / resolved：13 行（100%）
task_ref            只有 'refusal' 一个值
链分布              13 个链，每个链恰好 1 个节点
working_memory      9 槽，实际 slots=0、links=0
```

### 1.3 三条实证

**① 每条消息都是一条独立的链，链内永远只有 1 个节点。**

```
chain_for("refusal-2026-10-28") 连调两次 → 41da7312… / e77b24ab…（不相等）
```

`chain_for()` 的复用条件是「找到 `task_ref == 传入值` 的 open 节点」，而写入时 `task_ref` 固定是
`"refusal"`、调用时传的是 `"refusal-<日期>"`，永远匹配不上 → 每次新建链。桌面聊天更直接：
`dialogue_id` 默认是 `dlg-<时间戳>`，每条消息都是新值。**所以"链"目前只是形式，没有任何连续性。**

**② 13 个节点全是拒绝决策，不是"她在想什么"。**

`type=decision`、内容是 `请求：…｜信号 emotion=0.00…→ACCEPT`。也就是说：**QQ 对话根本没有被
沉淀成思考节点**——核心只收到桥接的"这条消息要不要拒绝"这一次调用，她回了什么、翻到什么记忆、
怎么想的，核心一概不知（`dialogue_message=0` 佐证）。

**③ 检索器其实不限链——补丁里那句"只认当前链"在这套代码里不成立。**

`retrieval.recall()` 走全库倒排 + 图邻居，没有任何 `chain_id` 过滤。真正的断点是：
注入只发生在 `thought_chain.context_block()`（取近 3h + open），而那段代码有个时间窗 bug（见 ④），
且工作记忆槽每拍 ×0.92 衰减，一两分钟就清空（现在 slots=0）。

**④ 顺手挖出一个真 bug：`thought.recent(hours)` 的时间窗是假的。**

```
datetime('now','localtime','-3 hours')  →  '2026-10-28 20:13:18'
'2026-10-28T18:00:00' >= 上面这个        →  1   ← 5 小时前的节点居然"在 3 小时窗口内"
'2026-10-27T18:00:00' >= 上面这个        →  0
```

`t_created` 是 `2026-10-28T18:00:00`（带 T），SQLite 的 `datetime()` 是 `2026-10-28 18:00:00`（带空格）。
逐字符比较时第 11 位 `'T'(0x54) > 空格(0x20)`，所以**凡是"今天"的节点全部通过**。
现在的 `recent(3h)` 实际等价于"今天零点以后"。v4 的注入窗口依赖时间距离，必须修。

## 二、根因结论：补丁诊断对了一半

| 补丁的说法 | 实际情况 | 影响 |
| --- | --- | --- |
| 「思维链按会话隔离注入，检索器只认当前链」 | **不成立**：检索器全库召回，没有链过滤 | 照原文实现也能跑，但理由要改 |
| 「会话结束 → 工作记忆槽清空 → 新会话冷启动看不见」 | **部分成立**：槽确实会衰减清空（现在 0 槽），但没有"会话"概念，也没有任何冷启动注入 | v4 方向对 |
| 「旧链节点仍在存储中只是进不来」 | **更糟**：旧链里根本没有对话内容，只有拒绝决策 | **只做残留通道解决不了你提的问题** |

**一句话**：残留通道是"把已经存在的东西捞回来"的机制，但现在**没有值得捞的东西**。
要让"上次对话的思维链"真的可见，v4 必须同时补两块前置，否则打开残留池只会看到
一行行「请求：…→ACCEPT」。

## 三、迁移方案（幂等，只增不改）

### 3.1 加三列 + 一张索引表

```sql
-- 仅在 PRAGMA table_info(thought_node) 里没有时执行
ALTER TABLE thought_node ADD COLUMN last_active_at TEXT;
ALTER TABLE thought_node ADD COLUMN in_residual INTEGER DEFAULT 0;
ALTER TABLE thought_node ADD COLUMN session_tag TEXT;

CREATE TABLE IF NOT EXISTS residual_index (
  node_id        TEXT PRIMARY KEY,
  chain_id       TEXT NOT NULL DEFAULT '',
  session_tag    TEXT NOT NULL DEFAULT '',
  last_active_at TEXT NOT NULL DEFAULT '',
  closed_at      TEXT NOT NULL DEFAULT '',
  in_residual    INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX IF NOT EXISTS idx_ri_active ON residual_index(in_residual, last_active_at);
```

- 只存索引，不复制正文（正文仍从 `thought_node` 按 id 读）。
- 老行 `last_active_at=NULL`、`in_residual=0`、`session_tag=''`，**不回填**；它们不参与残留，
  直到下次被访问/断开时自然写入。
- 不重算任何历史节点的 strength / salience / level / concepts。

### 3.2 新增配置 `config\residual.json`

```json
{
  "enabled": true,
  "w_fast": 0.65, "tau_fast_min": 8, "tau_slow_min": 55,
  "salience_boost": 0.5, "open_boost": 0.8,
  "level0_threshold": 0.50, "level1_threshold": 0.22, "level2_threshold": 0.08,
  "cold_start_topk": 6, "per_chain_cap": 3,
  "pool_capacity": 200,
  "idle_timeout_min": { "qq": 15, "desktop": 3 },
  "mood_bonus": 0.1
}
```

> `idle_timeout` 拆成两档：QQ 里你可能十几分钟才回一句，3 分钟会把同一段对话切成一堆"会话"。

### 3.3 `tools\migrate_v4.py`

与 v3 同一套骨架：`--dry-run` / 自动备份（db + state/*.json）/ 前后行数对比 /
任何表减少即还原并退出 1 / 幂等可重复。报告写 `db\backup\migrate-v4-<时间戳>.txt`。

**预期结果**：`thought_node 13 → 13`、`residual_index 新建 0`、`memory_item 646 → 646`，全部 +0。

## 四、残留通道接口设计

### 4.1 会话与链（前置 A，新增 `core/thought/session.py`）

```python
def touch(conv: str) -> dict          # 记录活动时间；超 idle_timeout → end(conv) 再开新会话
def current(conv: str) -> dict        # {session_tag, started_at, last_at, chain_id}
def end(conv: str, reason="idle") -> dict   # 结束会话：节点写 last_active_at/in_residual/session_tag
def chain_for(conv: str) -> str       # 同一会话复用同一条链（替代现在的 chain_for(dialogue_id)）
```

- `session_tag = f"{conv}#{序号}"`，存 `state\sessions_v4.json`（每个 conv 一条，文件很小）。
- `end()` 时把该 `session_tag` 下所有节点批量写三列 + 写入 `residual_index`。

### 4.2 回合节点（前置 B，新增 API + 桥接回传）

```python
# core/thought/turn.py
def record_turn(conv, *, user_text, reply_text, memory_ids=None,
                emotion_tag="平静", salience=0.55) -> dict
```

内容模板（这是"看得见"的关键，信息量必须够）：

```
老大说：{user_text}
我当时回：{reply_text}
翻到的：{memory 摘要 2~3 条}
```

- 生成 `type=step` 节点，`task_ref=conv`，`chain_id=session.chain_for(conv)`；
- 同一轮再挂一个 `reflection` 节点（`她为什么这么回`：口语化一句，来自 policy.tone + 主导情绪），
  这样"当时的想法"才是可读的，而不是只有决策。
- **桥接侧**：每轮回复发完后 POST `http://127.0.0.1:18766/api/thought/turn`
  `{conv, user_text, reply_text, memory_ids}`；核心不可用就丢弃（不阻塞 QQ）。

### 4.3 残留强度（`core/thought/residual.py`）

```python
def strength(node, now=None, vec=None) -> float
def tier(r: float) -> int | None                 # 0/1/2/None
def effective_level(node, tier) -> int           # max(node.level, tier)，墓碑不回正文
def register(session_tag, node_ids, closed_at) -> int
def pool(limit=200) -> list[dict]                 # 按 R 降序，带 Δ分钟/chunk/level/open
def sweep(now=None) -> dict                       # R<0.08 移出；超容量按 R 升序淘汰
def cold_start(conv, k=6, vec=None) -> dict       # top-k，跳过本会话已注入的
def inject_block(conv) -> str                     # 给语言系统的注入文本
def touch(node_id) -> None                        # 访问刷新：last_active_at=now，salience 微升
```

`R(t) = w_f·exp(-t/τ_f) + (1-w_f)·exp(-t/τ_s)`，`τ` 按 `salience` 与 `is_open` 放大
（规格 3.1 原式，参数全进配置）。情绪一致性 ×1.1 只影响排序。

**注入粒度**：`level = max(node.level, tier_level)`；
- level 0 → 原文 `content`
- level 1 → `summary`
- level 2 → `skeleton` + `concepts`
- node.level==3（墓碑）→ 只给 `concepts` + 已有结论，**不复活正文**

### 4.4 接入点（只加调用，不改主干）

| 位置 | 加什么 |
| --- | --- |
| `cognition/dialogue.py` 开头 | `session.touch(conv)` → 若是本会话第一条，`residual.cold_start(conv)` 并把 `inject_block` 拼进 `memory_block` |
| `dialogue` 返回前 | `turn.record_turn(...)` 落回合节点（含她自己的回复） |
| `cognition/loop.py` 每拍 | `session.touch` 空转无妨；`residual.sweep()` 交给 10 分钟巩固任务 |
| `consolidate.periodic()` | 加 `residual.sweep()`（每 10 分钟） |
| `retrieval.recall()` 命中 thought 节点时 | 额外 `residual.touch(node_id)`（访问刷新，**只加一行**，不改排序） |
| `thought.recent()` | 修时间窗 bug（改成 `datetime(t_created) >= datetime('now','localtime',?)`） |

### 4.5 UI（新增，不动现有树）

- 记忆系统 → 思维链 → **最近想法**：按 R 降序列出残留池（时间距离 / 档位 / R 条 / 是否 open / 所属会话）。
- 顶部一行：**本次会话冷启动注入了 N 条**（列出 id + 档位），可审计。
- 设置 → 高级 → 残留通道：开关 + 6 个参数（默认即上表）。

### 4.6 与既有逻辑的边界

| 既有逻辑 | v4 动不动 |
| --- | --- |
| 18h 瞬时清空 | 不动 |
| strength 衰减 / level 降级 / 蒸馏 / 墓碑 | 不动 |
| 检索器排序（strength×salience×相关性×情绪） | 不动（只加一次 touch） |
| 图结构 / refs / concepts 索引 | 不动 |
| 残留通道 | **叠加在可见性上**，不替代上述任何一条；两者取更压缩的 level |

## 六、需要你拍板的三件事

1. **QQ 回合节点要不要落**（前置 B）。不落的话，残留池里只有「拒绝决策」，你还是看不到"她当时怎么想的"。
   落的话要再动一次桥接（每轮多一次本机 HTTP，失败不影响 QQ），并重启一次。
2. **会话边界怎么定**：QQ 15 分钟 / 桌面 3 分钟（推荐，符合你回消息的节奏），还是统一 3 分钟？
3. **`thought.recent()` 的时间窗 bug 顺手修吗**。不修的话，"近 3 小时"实际是"今天全部"，
   残留注入的时间距离会失真（v4 自己算 Δ 不受影响，但旧的注入块会多塞东西）。
