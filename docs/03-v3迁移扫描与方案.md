## 二、迁移方案（增量，幂等，可回滚）

### 2.1 硬性做法

1. **不动任何现有列、不 DROP、不 DELETE、不重建库。**
2. 建表一律 `CREATE TABLE IF NOT EXISTS`；加列先查 `PRAGMA table_info`，缺了才 `ALTER TABLE ... ADD COLUMN`。
3. 新列全部 `DEFAULT NULL`，**不回填历史行**（历史记忆的 salience/strength/concepts 一律不重算）。
4. 迁移前备份：`db\backup\dafeiyu-v3-<时间戳>.db` + `state\backup\<时间戳>\*.json`。
5. 迁移前后各数一次行数；**任何表行数减少就自动还原备份并退出 1**。
6. `--dry-run` 只打印将要执行的 SQL 与预期行数，不写盘。
7. 成功后写 `schema_version=3`；重复执行只补缺，不重复加列/建表。

### 2.2 新增表（2 张）

```sql
CREATE TABLE IF NOT EXISTS vision_asset (
  id            TEXT PRIMARY KEY,
```

## 三、新增模块接口设计

### 3.1 视觉预处理（`core/vision/`）

```python
# preprocessor.py
@dataclass
class Tile:
    index: int; path: str; x: int; y: int; w: int; h: int; label: str
@dataclass
class VisionPlan:
    image_path: str; width: int; height: int; tiled: bool
    tile_size: int; overlap: int; tiles: list[Tile]; manifest: dict

class VisionPreprocessor:
    """输入任意图 → 切块/跳过 → 带坐标与标签的切块 + 全局缩略图 + manifest。"""
    def __init__(self, tile=800, overlap=40, max_tiles=64, small_skip=800, out_dir=None): ...
    def prepare(self, image_path: str, *, label: str = "") -> VisionPlan
    def aggregate(self, plan: VisionPlan, results: list[dict]) -> dict   # 按坐标聚合成结构化答案

# reader.py —— 识别适配器（可替换）
class VisionReader(Protocol):
    name: str
    def available(self) -> bool
    def read_tiles(self, plan: VisionPlan, question: str) -> list[dict]   # [{i, text, confidence}]

class DshAgentReader:   # 默认：把切块路径交给 dsh headless，让 agent 用自带 read_image 看
class NullReader:       # 兜底：只产出 manifest，不识别（记 evidence）

# store.py
def attach_vision(plan, report, *, memory_item_id="", kind="upload") -> str   # 写 vision_asset + 回填 memory_item.vision_tiles
```

切块规则：最长边 ≤ `small_skip`(800) → 不切，单块整图；否则按 `tile=800 / overlap=40` 切，超过 `max_tiles=64` 每隔 n 块抽一张并标 `sampled`。
坐标/标签进 manifest，聚合时按 `(x,y)` 排序拼接，输出「左上/中上/…/整体」的分区描述。

**决策点**：识别用 `dsh headless`（agent 自带看图工具），每图/每批一次调用。

### 3.2 自主学习浏览（`core/learning/browse.py`）

```python
class WebVisionTool:
    name = "web_vision"
    def available(self) -> bool
    def browse_and_screenshot(self, url: str, wait_seconds: float = 3.0,
                              full_page: bool = True) -> dict   # {ok, path, title, width, height}
```

- 底层 `playwright`（可选装），用**系统 Edge**（`channel="msedge"`），不下载 Chromium。

### 3.3 拒绝仲裁（`core/refusal/`）

```python
# signals.py
def score(request: dict, vec, meta: dict) -> dict
# → {"emotion":0..1, "will":0..1, "competence":0..1, "boundary":0..1, "fatigue":0..1, "relationship":0..1}

# arbiter.py
@dataclass
class RefusalDecision:
    id: str; t: str; request_summary: str; signals: dict
    propensity: float; threshold: float
    decision: str          # ACCEPT|REFUSE|NEGOTIATE|DEFLECT|RELUCTANT_ACCEPT
    reason_text: str; style: str; alternatives: list[str]
    user_reaction: str = ""; reacted_at: str = ""
    linked_thought_node_id: str = ""; linked_intent_id: str = ""

class RefusalArbiter:
    def decide(self, request: dict, vec, policy) -> RefusalDecision
    def react(self, decision_id: str, reaction: str) -> None      # 用户后续反应（奖罚联动）
    def status(self) -> dict                                      # 预算/傲娇余额/阈值

# store.py：refusal_decision 表 + state/refusal.json + state/refusal_log/*.jsonl
# style.py：从 1 号长期记忆读性格参数，生成与情绪一致的一句话理由（禁模板）
```

**决策流程**（在响应策略之后、生成之前）：

```
propensity = clamp(0.22*emotion + 0.16*will + 0.14*competence
                   + 0.28*boundary + 0.12*fatigue + 0.08*relationship)
if boundary ≥ 0.9 且不在黑名单：→ REFUSE（安全类强制）
若命中黑名单（安全/紧急/核心操作）→ ACCEPT（或安全替代）
propensity < threshold        → ACCEPT
threshold ≤ p < threshold+δ   → NEGOTIATE（给条件/替代）
p ≥ threshold+δ 且 shy 高、正面不低 → RELUCTANT_ACCEPT（傲娇，真实执行）
p ≥ threshold+δ 且 fatigue 高 → DEFLECT（延后）
否则 → REFUSE
预算/傲娇上限耗尽 → 自动降级为 NEGOTIATE / 正常表达
连续拒绝 N 次 → 下一次强制 ACCEPT（关系修复）
```

默认值（`config/refusal.json`）：

| 项 | 默认 | 含义 |
| --- | --- | --- |
| threshold | 0.62 | 拒绝阈值 |
| negotiate_band | 0.10 | 阈值上方 0.10 内先协商 |
| refuse_per_hour | 3 | 每小时 REFUSE/DEFLECT 上限 |
| tsundere_per_hour | 2 | 傲娇上限 |
| tsundere_level | 0.4 | 性格参数（0~1） |
| repair_after | 3 | 连拒几次后下一次倾向接受 |
| allow_deflect | true | 是否允许 DEFLECT |

**联动**：
- 情绪：用户尊重拒绝 → `reward.apply_trigger("cared")`；被强迫/被无视 → 惩罚项。
- 记忆：每次决策写一条 `thought_node(type=decision)`（含 signals/threshold/decision/reason），并把被拒请求写瞬时记忆；反复被强迫的条目 salience 上调（沿用现有 boost，不重算历史）。
- 好奇心：能力不足的 DEFLECT → `LearningIntent(gap_type=skill_failure)`，学完后回访。
- 审计：`state/refusal_log/` + `audit_event`。

### 6.2 与方案的偏差（都是往更稳的方向偏）
