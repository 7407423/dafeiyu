## 一、现有视觉入口结构（扫描）

```
QQ 图片 ──► qq-bridge/media-normalize.js ──► normalizeImageForModel()
              ├─ GIF：自研解码器 parseGif() + ffmpeg 抽 6 帧 + 240px 拼图
              └─ 其他：降采样到 maxLongEdge
                    │
                    ▼ 只在「喂模型」的出口调用（toModelMedia）
             DSH agent（她调用 qq_get_message_images 时才走这条路）

桌面/学习 ──► core/vision/pipeline.analyze()
              ├─ preprocessor：QImage 读图（**只读第一帧**）→ 800×800 切块
              ├─ reader：dsh headless 逐块看 → JSON
              └─ store：vision_asset + memory_item.vision_tiles
```

关键事实：

| 项 | 现状 |
| --- | --- |
| 桥接的 GIF 支持 | **已经有**：`media-normalize.js` 里有 `gifFrames: 6` / `gifTile: 240`，注释写明「DSH 的 canPassThroughNormalization() 显式排除 image/gif」——也就是说**这条路是为绕开单帧归一化专门写的** |
| 图片是否自动进模型 | **不自动**。bridge 在消息里只放一句提示：`【图片/表情】本条消息包含 N 个图片/表情（消息ID=…）。如需要查看/识别，请调用 mcp__…qq_get_message_images` |
| 核心侧（桌面/学习） | 只有静态切块，**没有 GIF/WebP 分支**，也没有任何缓存 |
| `memory_item.animation_meta` | 不存在 |
| 表情包字典 | 不存在（DSH 只装了 `qq-agent-presets`、`qq-mode-console`，补丁点名的 `dsh-sticker-dict`、`dsh-read-animation` 都没装） |

**所以「看不见动图」的真实原因不是「被归一化成单帧」，而是：她不主动调用看图工具。**
就算把帧抽得再细，她不调就还是只看到「[动画表情]」。而这套桥接的 GIF 抽帧是她一调就能用的。

| 让大肥鱼看见动图 | **能，且大部分已经在跑** | 真正缺的是三件：① 表情包**缓存**（同一张不重复识图，省钱）② 让她**愿意/自动**去看（桥接提示升级 or 自动带图）③ 核心侧（桌面/学习）补 `AnimatedDecoder` |

   桥接自带 GIF 抽帧，核心侧用 QImage 自己做（和 v3 切块同一套，零新依赖）。插件接口留成适配器即可。

   「语音消息数 / 语音相关对话轮次」这类可比指标。

```python
# core/llm/provider.py

```
`_record()` 里除了写 `llm_usage.jsonl`，再调 `cost.record_event(...)` 写 `cost_event`（含 estimated 与 actual）。

### 5.2 费用归因

```python
# core/cost.py（扩展，不重写）
def record_event(feature_tag, *, task, model, usage, estimated, actual, session_id="", message_id="", meta=None) -> str
def attribute(days: int | None = None, start: str = "", end: str = "", tags: list[str] | None = None) -> dict
    # → {"total": {...}, "by_day": [...], "by_tag": [...], "deviation": {...}, "unclassified": n}
def backfill_from_ledgers() -> int      # 把两个 jsonl 账本里"还没进 cost_event 的"增量补进去（幂等，不猜历史）
def import_bridge_ledger() -> int       # bridge token-usage.jsonl → cost_event(source=bridge, tag=chat/chitchat)
def export_csv(path: str, **filters) -> str
```

`estimated_cost` 的算法（诚实版）：
- 调用前：`estimate_tokens(prompt)` × 输入单价 + **该 feature 历史平均输出 token** × 输出单价；
- 调用后：用实际 usage 按**调用时刻**的峰谷档重算 → `actual_cost`；
- 历史没有 estimated 的记录，`estimated_cost = 0` 且视图标「无预估」，**不用 actual 冒充**。

### 5.3 动画解码

```python
# core/vision/animated.py
@dataclass
class AnimationPlan:
    sheet_path: str; frames: int; width: int; height: int
    duration_ms: int; loop: int; frame_indices: list[int]; source_sha256: str

class AnimatedDecoder:
    def supports(self, path) -> bool          # gif/webp/apng
    def decode(self, path, frames=5, cell_px=140) -> AnimationPlan   # 均匀抽帧 + 网格拼图 + 帧号标注
    def cached(self, sha256) -> dict | None    # sticker_cache 命中
```

- `preprocessor.prepare()` 开头分流：动图 → `AnimatedDecoder`（不进静态切块），静态图逻辑**原样不动**。
- 识别结果写 `memory_item.animation_meta`（JSON：帧数/时长/loop/帧索引/sha256/缓存命中）；
  concepts 写「动态表情 + 动作标签 + 情绪色彩」。
- 同一 sha256 第二次出现：**直接复用上次结论，不调视觉模型**（`cost_event` 记 0 花费，但记一次 `cache_hit`）。
- 情绪色彩只做轻微波动（`shyness/joy` ±2 级别），不当强奖罚事件。
