## v29：命中缓存就不再「发图」，改发描述

### 为什么要改

以前命中本地字典只是把描述塞进提示词末尾（`【图片内容·已自动识别】`），**图片字节照发**。
于是每一轮都在付两笔：一次图片输入 token（几千 token），加上偶尔她自己去调看图工具。

### 改成什么

桥接 `resolveMediaList()` 里，取到图片字节后先算 sha256 查字典：

- **命中**：不生成 image part，改生成一段文字（这就是「系统悄悄话」）：

  ```
  [系统悄悄话：用户发送了一张图片，你已经认出来了，它的内容是：“一只脸上有个问号的猫”。
   请假装你看到了这张图，直接根据这个内容用你的人设回复用户。不要调用任何视觉工具。]
  ```

  日志会留痕：`[sticker] 字典命中 3f2a…（图片）→ 本轮只发描述，不发图片字节`

- **未命中**：原样发图（她能看见），同时后台上那次识别会把描述写进字典，**下一轮**就走命中路径。

多图天然按顺序拼：`resolveMediaList` 本来就是 `for … await` 串行，所以三张图会依次产出
「文字 → 描述 → 文字 → 描述 → 文字 → 描述」，顺序和用户发的顺序一致。

### 和补丁描述的差异（要说清楚）

补丁说要替换消息里的 `[图片]` 占位符。这里没有占位符可替换 —— 我们的消息体是
**多模态 part 数组**（`{type:'text'}` + `{type:'image'}`），所以等价做法是
「命中时**不生成** image part，只生成 text part」。效果一样：模型拿到的就是那段话。

### 验收

| # | 验收 | 结果 |
| --- | --- | --- |
| 1 | 发一张图能正常回复 | ✅ 未命中走原路径 |
| 2 | 同一张图再发，描述被拼进 prompt | ✅ 命中分支生成悄悄话 |
| 3 | 后台没有任何视觉计费 | ✅ 命中路径**根本不发图片字节**，也没有 `/api/vision/analyze` 调用 |
| 4 | 用户无感 | ✅ 纯底层行为，不碰 DB、不加配置 |

## v31：内稳态（身体需求）

### 三个变量

| 变量 | 含义 | 设定点 | 怎么变 |
| --- | --- | --- | --- |
| `energy` | 能量 | 0.8 | 活跃时 −0.020/分；闲置 ≥10 分钟后 +0.012/分 |
| `social_connection` | 社交连接 | 0.6 | 一直 −0.010/分；收到一条消息 **+0.28** |
| `cognitive_novelty` | 认知新颖性 | 0.5 | 一直 −0.008/分；学完一批 +0.35、刷完视频 +0.28 |

初始值就是设定点（不假装她天生很累）。tick 按 **elapsed 分钟**算，所以补跑 12 小时、
关机 3 天再开机都不会算错（上限 24 小时）。

### 动机与仲裁

```
fatigue    = max(0, 0.8 − energy)
loneliness = max(0, 0.6 − social_connection)
boredom    = max(0, 0.5 − cognitive_novelty)
dominant   = argmax(三者)，且强度 ≥ 0.05，否则算「平静」
```

### 情感着色（不改情绪存储，只加增量）

| 主导 | 对情绪向量做什么 |
| --- | --- |
| loneliness | `难过 +0.05×s`、`幸福 −0.02×s` |
| fatigue | `愉悦 −0.03×s`、`害羞 −0.02×s` |
| boredom | `愉悦 −0.015×s` |

走 `emotion.vector.apply()`，仍然受既有的「越阈保护」约束（刚被刺激过的维度不会被覆盖）。
着色失败一律吞掉 —— 情绪坏了不能把心跳也带停。

### 挂载

- `core/cognition/scheduler.py`：`IntervalTrigger(seconds=60)` 的 `homeostasis` job；
- `core/api.py`：`/api/homeostasis/state`（含给提示词的 `block`）、`/api/homeostasis/event`；
  收到消息时（`/api/thought/turn`、`/api/dialogue`）自动 `note("user_message")`；
- 桥接：唤醒提示词里插入【身体感觉】三行（一分钟拉一次，缓存 60 秒，不额外花钱）；
- UI：情绪面板新增「内稳态」三根条 + 主导动机/表达欲/熔断状态。

## v32：内稳态 → 好奇心（三位一体）

### 三个联动点

1. **无聊 → 启动**：`boredom > 0.3` 时把好奇心的门槛压下来
   （`threshold × (1 − 0.4×boredom)`，下限 0.2）。**不改** `calculate_urgency` 的公式，
   只改「够不够格」。
2. **孤独 → 定向**：`loneliness > 0.2` 时，对「人际/梗/搞笑/用户/热门/视频/情绪」这类领域
   的紧迫度乘 `1 + 0.8×loneliness`，让她难受时去学能跟人聊起来的东西。
3. **疲劳 → 熔断**：`energy < 0.2` 时 `curiosity_engine.tick()` **直接返回**
   `{"skipped": "太困了（…），这一轮不学了", "fuse": true}`，不建任何学习意图。

### 日志轨迹

```
[内稳态] 无聊 0.42/孤独 0.10 → [好奇心] 选定「聊梗」(0.61)
```

## 已知边界

1. **着色幅度是小的**（0.01~0.05/分钟级），故意的：内稳态是「底噪」，不该盖过被骂/被夸的快回路。
2. **能量回血的门槛是 10 分钟无互动**。一直在聊 = 一直在耗，符合直觉。
3. **没有做「困了就睡」**。夜间关机是另一套（02:20 关机），内稳态不参与进程生命周期。
4. 熔断只拦**自主**好奇心（`curiosity_engine.tick`），不拦对话里她自己想查东西 ——
   那是老大在问，不该因为「她困了」就拒绝回答。
