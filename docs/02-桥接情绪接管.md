## 二、桥接要改的两处（约 40 行）

### 1) `src/emotion-engine.js` — 加一个「只读/上报」模式

在 `createEmotionEngine({ file, log })` 的签名里加一个可选参数，并在 `applyDeltas` 里分流：

```js
export function createEmotionEngine({ file = DEFAULT_FILE, log = () => {}, core = null } = {}) {
  // …原有代码…

  async function reportToCore(text) {
    if (!core?.url) return false;
    try {
      const res = await fetch(`${core.url}/api/emotion/event`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ text })
      });
      return res.ok;
    } catch (error) {
      log(`[emotion] 核心不可用，回退本地：${error?.message ?? error}`);
      return false;
    }
  }

  function adopt(state) {
    if (!state?.emotions) return;
    s.emotions = { ...s.emotions, ...state.emotions };
    s.updatedAt = state.updatedAt || new Date().toISOString();
    dirty = false;              // 不落盘：状态文件由核心写
  }

  // onIncoming 里：
  //   if (core?.url && await reportToCore(text)) { adopt(await readCoreState()); return; }
  //   否则走原来的本地逻辑
}
```

1. `config\app.json` → `bridge.emotion_mode` 改回 `"local"`。
2. 桥接 `config.json` → `dafeiyu.emotionMode` 改 `"local"`（或删掉）。
3. 重启桥接。

回退后一切照旧：桥接自己算、自己写，核心在下一个 tick 对齐它的数值。

## 四、接管后会发生什么

| 变化 | 说明 |
| --- | --- |
| QQ 消息的情绪由核心算 | 奖罚/尺度识别只有一套，桌面和 QQ 永远一致 |
| `状态.json` 由核心写 | 桥接只读，不再有「谁后写谁赢」的抖动 |
| 核心没开时 | 桥接上报失败 → 自动回退本地算，不会哑 |
| 桌面端的对话也会影响情绪 | 因为写的是同一个 `EmotionVector` |
| 延迟 | 多一次本机 HTTP（<5ms），可忽略 |
